# PRD-10 交付质量与自动验证闭环

## 目标

让 Agent 从“会改代码”升级为“可自证交付质量”：自动测试、静态检查、回归校验、失败自修复闭环。

## 范围（In Scope）

- Validation Pipeline（lint/test/build）。
- 失败分类与修复策略（可重试、需人工、需审批）。
- 变更影响分析（受影响文件与测试集）。
- 最终交付报告（通过项/失败项/风险项）。

## 非目标（Out of Scope）

- 全自动 PR 合并策略。
- 复杂混沌工程体系。

## 功能要求

- 标准验证阶段：`lint -> test -> build`。
- 失败结果结构化：`stage/code/message/suggestion`。
- 允许定义“必过门槛”。
- 失败后最多 N 次自动修复重试（可配置）。
- 输出统一 `delivery_report.json`。

## 验收标准（AC）

- AC-10-1：每次实现后自动执行验证流水线。
- AC-10-2：失败可给出明确修复方向，避免“只报错不解释”。
- AC-10-3：重试策略可减少人工介入次数。
- AC-10-4：交付报告可直接用于评审与归档。

## 实施顺序

1. 先搭建验证流水线执行器。
2. 再做失败分类与自动重试。
3. 最后落交付报告与质量门槛配置。
