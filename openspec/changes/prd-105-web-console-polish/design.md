## Context

本地项目已启动为 `agent service -> BFF -> web-console` 三段链路，Web 端页面可访问且 BFF health 正常。真实浏览器截图显示页面主体可用，但顶部左侧侧栏按钮出现了 `0` 字符，说明 CSS icon 绘制存在兼容或样式覆盖问题；同时 README 仍保留旧 Dashboard 与 Vite middleware 数据源说明，容易误导下一轮开发。

## Decisions

1. 优先修复当前页面可见瑕疵，不扩展交互范围。
   - 理由：继续开发前先让现有首屏达到可信状态。
   - 备选：直接开始新增大功能。未采用，因为当前 UI 和文档仍有明显不一致。

2. 图标仍使用现有 CSS 绘制方案，不新增图标库。
   - 理由：当前 Web app 未引入 lucide 或其他图标依赖，本轮只做小范围 polish。
   - 备选：引入图标库。未采用，因为会扩大依赖和验证范围。

3. README 更新为当前运行事实。
   - 理由：当前 Web 已经只通过 BFF `/api/*` 访问 agent 能力，不再是读取本地文件的只读 Dashboard。
   - 备选：保留旧 README。未采用，因为会让启动和架构边界说明失真。

## Risks

- CSS 图标修复可能只覆盖当前可见按钮，后续若继续保留手写图标，需要在更系统的 UI pass 中统一治理。
- README 更新只描述本地开发链路，不解决公网部署、认证或多用户场景。
