## Context

左侧区域目前直接显示 `Agent` 品牌、占位功能入口和全量 session 列表；session 只能选择和新建，不能做轻量管理。由于 agent service 暂无删除、重命名、置顶 endpoint，本轮不应扩大后端边界，而是在 Web 层用 localStorage 维护 display metadata：标题、置顶、隐藏。

## Decisions

1. 会话管理状态保存在 Web localStorage。
   - 理由：本轮是左侧体验优化，不改变 agent runtime 与 session 持久化格式。
   - 备选：新增后端 endpoint。未采用，因为会扩大服务协议和测试范围。

2. 删除操作在 Web 侧隐藏会话。
   - 理由：当前没有后端删除 API；“删除”对侧栏列表生效，避免误删真实 agent 历史文件。
   - 备选：BFF 直接删除 `.sessions` 文件。未采用，因为会绕过 agent service 数据边界。

3. 置顶优先于更新时间排序。
   - 理由：用户置顶的会话应稳定留在列表上方，非置顶仍按更新时间倒序。

4. 待开发入口保留原分类名称，并显示统一待开发状态。
   - 理由：仍能表达未来信息架构，同时避免用户误点后困惑。

5. 折叠动画使用 CSS transition。
   - 理由：不引入动画库，保持轻量且可由 `prefers-reduced-motion` 关闭。

6. 左侧不再保留底部连接状态块。
   - 理由：底部状态块占用历史列表空间，顶部已有紧凑连接状态图标，保留单一入口即可。

7. 消息角色信息放在消息正文外部。
   - 理由：用户消息气泡应只承载用户输入内容，角色名称与头像作为消息行元信息呈现，与 AI 回复保持一致。

8. 页面图标统一使用 Lucide。
   - 理由：手写 CSS 图标一致性和精致度不足，统一图标库可以提升页面观感并降低后续维护成本。

9. 左侧底部新增个人设置入口。
   - 理由：连接状态块移除后，底部区域更适合承载用户偏好、自定义和系统设置等稳定入口。

## Risks

- Web localStorage 管理状态只在当前浏览器生效，清空浏览器存储会丢失重命名、置顶和隐藏状态。
- 删除是 Web 侧隐藏，不等于删除 agent service 的真实 session 数据；后续如要真删除，需要独立设计 agent service endpoint。
