# 增量 PRD 拆分总览

目标：将 `agent_prd.md` 的全量范围拆成可独立交付的小 PRD，按阶段实现、按阶段验收。

## 使用方式

1. 只打开并实现“当前阶段”文档，避免一次性实现全部能力。
2. 每阶段完成后执行该阶段 AC（验收标准），通过后再进入下一阶段。
3. 未进入阶段的能力统一视为 `Out of Scope`，不提前实现。

## 阶段路线图

- PRD-00：核心循环与最小可用 Agent（对应 S01）
- PRD-01：多工具与文件操作（对应 S02）
- PRD-02：任务可视化与持久化（对应 S03 + S07）
- PRD-03：子代理与技能加载（对应 S04 + S05）
- PRD-04：上下文压缩与后台任务（对应 S06 + S08）
- PRD-05：团队通信与协议（对应 S09 + S10）
- PRD-06：自治与 Worktree 隔离（对应 S11 + S12）

## 建议节奏

- 一次只做一个 PRD。
- 每个 PRD 产出：代码 + 最小可运行演示 + 验收记录。
- 每个 PRD 最多 1-3 天，避免跨度过大。

## 进入下一阶段的门槛

- 当前阶段 AC 全部通过。
- 关键风险已记录（即使未完全消除）。
- 现有 CLI 可继续稳定运行。
