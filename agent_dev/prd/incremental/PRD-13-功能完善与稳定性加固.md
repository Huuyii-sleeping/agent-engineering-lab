# PRD-13 功能完善与稳定性加固（P0）

## 目标

在暂停新增大功能的前提下，对 PRD-00 ~ PRD-06 已实现能力做系统性完善与加固，提升稳定性、一致性、可维护性和可用性。

## 优先级

- **P0（最高优先级）**：先做本 PRD。
- **P1 及以后**：再推进 PRD-07+ 新能力扩展。

## 范围（In Scope）

- 错误码统一与失败路径补全（工具层/协议层/自治层）。
- 并发与锁机制加固（认领锁、后台任务状态竞争、通知队列一致性）。
- 配置化改造（阈值、轮询间隔、超时参数统一配置入口）。
- 数据结构补全与向后兼容（task/team/worktree schema 演进）。
- 回归测试集（覆盖关键成功/失败场景）。
- 文档补完（每个工具输入约束、边界、失败码、示例）。

## 非目标（Out of Scope）

- 新的跨域能力（例如新增商业化计费、复杂调度器）。
- 与外部平台的大规模集成。

## 功能要求

- 所有核心工具必须返回结构化错误：`{ ok:false, error:{ code, message } }`。
- 每个关键状态机补齐非法状态转移保护：
  - task 状态
  - team 协议请求状态
  - subagent 状态
  - autonomy 状态
  - worktree 生命周期状态
- 所有“默认常量”迁移到统一配置层（可覆盖）。
- 对持久化文件增加 schema version 字段并处理旧版本兼容读取。
- 新增 smoke + regression 测试入口（可一键执行）。

## 验收标准（AC）

- AC-13-1：核心工具（task/team/subagent/worktree/autonomy/background/compact）均有成功与失败测试。
- AC-13-2：并发认领与并发协议响应场景下无重复执行、无状态错乱。
- AC-13-3：配置修改后无需改代码即可生效（通过环境变量或配置文件）。
- AC-13-4：回归测试一次性通过，且能稳定复现历史关键场景。
- AC-13-5：工具文档与错误码字典完整，开发者可直接查阅使用。

## 实施顺序

1. **稳定性基线**：盘点现有失败路径与未覆盖边界，补全错误码与状态保护。
2. **配置治理**：收敛常量与默认值，统一配置读取与校验。
3. **并发与一致性**：重点修复锁、状态竞争、重复通知问题。
4. **测试与文档**：建设回归套件，补齐文档并形成发布检查清单。
